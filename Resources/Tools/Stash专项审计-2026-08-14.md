# Stash 专项审计与去依赖路线（2026-08-14）

## 结论

Peach 最终可以完全去 Stash，但现在不能直接卸载。Web 主链已以 ledger 为真相源并自行串流；真正依赖仍分散在元数据写入、扫描回灌和二进制路径。正确做法是先集中成可替换 Stash adapter，再逐项由 Native Media Engine 接管。

## 运行态证据

- Stash v0.31.1 / schema 85，实际监听 `127.0.0.1:9999`，没有配置 username/password/API key。
- 2,551 Scene；2,002 Performer 关系、15,354 Tag 关系、2,551 Studio 关系；2,551 OSHash、1,953 pHash。
- GraphQL 实际暴露 screenshot/preview/stream/webp/vtt/sprite，以及 Direct、MP4、WebM、HLS、DASH、original/480p/240p stream。
- Stash generated 实际只有 80 sprite + 80 VTT（约 17.5 MB），transcodes/screenshots 为空。
- Peach 自有 snapshots 11,457 个（约 1.8 GB）、posters 855、avatars 50，覆盖范围并不等价。
- 代码中 19 个非文档文件直连 Stash GraphQL，11 个文件硬编码 Stash 私有 `ffmpeg-btbn` 路径。

## 逐项判断

| 能力 | Peach 必须适配而自研 | 应复用 | 当前重复，应替换/删除 |
|---|---|---|---|
| 扫描/探测 | 多来源发现、计费/缓存/重试、稳定映射 | FFprobe；过渡期 Stash Scan | Stash→ledger 双跳；多套探测和二进制定位 |
| 元数据 | canonical entity/alias/provenance/external ref | Stash GraphQL 导入；来源正式 API | `studio→creator` 错映射；Performer 扁平标签；只取 files[0] |
| 缩略图/预览 | 跨本地/网盘的成本策略和缓存状态 | FFmpeg；VTT+sprite；Stash fallback | 多套 sheets/contact/index/poster/avatar 管线 |
| 播放/转码 | 来源解析、成本、鉴权、行为事件、fallback | Starlette FileResponse；FFmpeg；HLS/DASH；Stash streams | 手写 Range 缺 suffix/416/If-Range/ETag；无 codec fallback |
| 搜索 | 跨来源、别名、行为/成本排序 | SQLite FTS5；过渡期 Stash filter | `LIKE` + 平面标签不足；不引入独立搜索服务 |
| Tag/人物/Scene | 实体关系、角色、来源置信度、多文件模型 | 借鉴公开概念和 GraphQL 协议 | `演员:` 字符串、自由文本唯一模型、19 套 GraphQL client |

## 已证实缺陷

- `rm-ledger.py cmd_stash()` 曾把 `studio.name` 写入 `asset.creator`，且不写 `studio`；本轮已修复并新增隔离回归测试。
- `rm-ledger.py scan` 的“已消失”只统计，不保存明确 missing 状态。
- `rm-probe.py` 失败写 `duration=-1`，而候选只取 `duration IS NULL`，失败项不会自动重试。
- `asset_tag` 的唯一键是 `(asset_id,tag)`，`INSERT OR IGNORE` 无法保存同一断言的多来源 provenance。

## 迁移阶段

1. 建立 `MediaBackend`、集中 Stash GraphQL adapter、独立 FFmpeg resolver。
2. 正规化实体/关系/provenance/external_ref，完整把 Stash 知识单向导回 ledger。
3. 用 NativeProbe/NativePreview/标准 Range/HLS 覆盖本地和网盘；Stash 只作 fallback。
4. 所有整理工具先写 ledger，需要时再 exporter 到 Stash。
5. 同批资产影子对比并关闭 adapter；保留备份与回退期。
6. 依赖归零后才卸载 Stash 和 generated 数据。

## 2026-08-14 第二阶段进展

- 新增集中 `StashClient`，FastAPI/Media Engine 新代码不再各自实现 GraphQL transport。
- 新增独立 `FFmpegResolver`：环境变量/Peach 托管目录/PATH 优先，Stash 私有目录只作可关闭 fallback。
- FastAPI 已用 Starlette `FileResponse` 替换候选入口的手写 Range，并验证普通、指定区间、suffix、
  越界 416、HEAD、ETag、Last-Modified。
- 旧 19 个脚本直连和 11 个硬编码依赖尚未归零；不能因此宣称已经去 Stash。

## 验收门槛

关闭 Stash 前必须完成：2,551 Scene 全关联；842 Performer、126 Tag、140 Studio 与全部关系、别名、hash 有 external ID/provenance；24,980 视频探测覆盖不回退；10,714 个账本 snapshot 仍可访问；常用和异常 Range、seek、两路并发及不兼容编码转码通过；关键别名/Studio/组合标签/云资产搜索一致；19/11 个依赖计数归零；关闭和回退均演练。
