## 六、必须知道的坑（这是本文档最有价值的部分）

### 6.1 标签词典的匹配是无词边界子串

`rm-tagmap.ps1` 在 `rm-import.ps1` 里的用法是 **`$rel -like "*$kw*"`** —— 对**完整相对路径**做
大小写不敏感的子串匹配，**没有词边界**。

实测踩过的雷：

| 关键词 | 误命中 |
|---|---|
| `3p` | `[13P+5V]` —— 这个圈子里 `13P` 是「13 张图」的通用写法 |
| `cn` | 任何含 cn 的路径，包括 `.cn` 域名 |
| `OL` | LOL / COOL / VOLUME |
| `2d` | UUID 里的十六进制（`e3d92a4c`） |
| `ts` | GETS / TITS / `.ts` 扩展名 —— **误判过 1,500 GB** |
| `91` / `TG` / `sm` | 数字编号 / TGP / smile |
| 别名 `rina` | `Katarina`（LoL 角色） |

**改词典后必须跑短 ASCII 关键词自检**：

```powershell
. "R:\Resources\Tools\rm-tagmap.ps1"
foreach($k in $Global:TagMap.Keys){ foreach($v in $Global:TagMap[$k]){
  if($v -match '^[A-Za-z0-9]{1,2}$'){ "⚠ $k -> '$v'" } } }
```
目前只剩 `jk`/`JK`（已知可接受）。

### 6.2 `$DirTags` 的键是目录名，目录改名后必须同步

2026-08-12 那次重命名后有 4 个键过期，差点摘掉 177 个场景的 `3D动画` 标签。
改目录后跑这个自检：

```powershell
. "R:\Resources\Tools\rm-tagmap.ps1"
$actual = Get-ChildItem 'R:\Media\创作者' -Directory | Select-Object -Expand Name
$Global:DirTags.Keys | Where-Object { $actual -notcontains $_ }   # 应为空
```

### 6.3 `rm-import.ps1` 只加标签不删

要清理误判标签必须用 `rm-tagclean.py`，它的做法是**算「旧词典会给、新词典不给」的差集**，
而不是「当前词典不会给的一律删」—— 后者会删掉全部人工标注
（`多女出镜`/`男主频道`/`身份待确认`/`足部射精` 等词典里根本没有的标签）。

### 6.4 网盘的成本模型（实测，不要凭直觉）

| 操作 | 成本 | 结论 |
|---|---|---|
| 列目录、读大小/时间、**改名、移动、删除** | 元数据操作，全盘扫描 529 秒 | 随便做，控频即可 |
| **seek 抽帧、ffprobe** | 与文件大小无关（8.5 GB 和 0.36 GB 一样快） | **可以全库做** |
| 解压、完整 PHash、整文件下载 | 需要完整传输 | 只对必要的做 |

ffprobe 命令形式差异极大：

```
不加 -select_streams 的完整 -show_streams   0.6 ~ 9.6 秒
加 -select_streams v:0 + 限定字段            0.04 ~ 0.07 秒（热）/ 0.87~1.56 秒（冷）
```
**慢 20~160 倍。** 音轨检测另需约 1 秒/文件，不值得。

### 6.5 「站点前缀 ≠ 广告」

`www.98T.la@`、`hhd800.com@`、`fulibl.net` 这类是**转载方给正片打的标记**，
不是广告特征。把它当广告判据会命中 5,114 个**正片**。该做的是改名去掉前缀。

真正的广告判据：文件名里**嵌了域名**（`uum58.com`、`TY996.COM`）且体积小、
推广话术（裸聊/信誉保证/棋牌/最新地址/发布器）、同名散布在 ≥3 个目录。

### 6.6 多线程脚本里的自锁（已解决，但值得记住排查方法）

**症状**：进程活着、CPU 接近 0、`ffprobe` 子进程数为 0、日志停在第一行、
账本数字长时间不动。看起来像「环境有问题」。

**真因**：worker 在**持有锁的情况下**调用了 `log()`，而 `log()` 内部还要再拿同一把锁：

```python
lock = threading.Lock()          # ✗ 不可重入
...
finally:
    with lock:                   # worker 拿到锁
        done[0] += 1
        if done[0] % 50 == 0:
            log(...)             # log() 内部又 with lock: → 自己锁死自己
```

第一个触发日志的 worker 把自己锁死且永不释放，其余 worker 全堵在同一把锁上。

**修法**：`lock = threading.RLock()`。`rm-probe.py` 和 `rm-sheets.py` 都已修。
**新写多线程脚本时注意同一个陷阱。**

修复后立刻从 0 变成 **4.0 个/秒、0 失败、预计 90 分钟跑完全库**。

**排查教训**（走了四条弯路，全错）：

| 怀疑过 | 为什么看似成立 | 实际 |
|---|---|---|
| 多实例抢 SQLite 写锁 | 确实有三个 python 并存 | 是反复重启造成的，不是原因 |
| 计划任务看不到网盘盘符 | 计划任务环境常有此问题 | 实测 `dir B:\` 正常 |
| 坏文件卡满 60 秒超时 | 前台跑确实有 4 个失败 | 那 4 个失败本身就是死锁的副作用 |
| `Start-Process` 挂在会话上 | 任务确实消失过 | 这条是真的（见下），但不是卡死的原因 |

**正确的第一步应该是看进程在等什么** —— `CPU 0.9 秒 + 子进程数 0` 已经说明它不是在干活而是在等锁，
而不是去改环境和参数。

### 6.6b 无人值守的启动方式

- `Start-Process -WindowStyle Hidden` **仍挂在调用它的会话上**，会话一断就被杀
- Windows 计划任务可用（`schtasks`，任务名 `RM-Probe` / `RM-Sheets` 已注册），
  盘符在计划任务里可见，验证过
- 最省事的是让用户双击 `run-probe.cmd` 开着窗口跑 —— 既脱离 AI 会话又看得见进度

### 6.7 SQLite 多实例会互锁

多个 `rm-probe.py` 实例并存会互抢写锁全部卡死。已加锁文件保护
（`R:\Resources\Intake\.probe.lock`），但**强杀进程后要手动删锁文件**。

### 6.8 其他

- 删除操作的 `Remove-Item` 会被安全守卫拦（误判成系统路径），用 `cloud-delete.py`（Python + 路径白名单）
- CSV 里 `文件数` 列名可能重复，`Import-Csv` 会拒绝，需手工解析
- PowerShell 的 `[ordered]@{}` 转 JSON 结构特殊，Python 侧直接正则解析 `.ps1` 更可靠
- 115 大小写敏感：`UraLesbian.com` / `uralesbian.com` / `UraLesbian` 是三个不同目录
