# 命名规范

> 2026-08-13 立。适用于本地 `R:\Media`、115、PikPak。
> 目录结构不在本文范围 —— 沿用既有约定：`R:\Media\创作者\{创作者}\` 只分一层，类型全走 Stash 标签。

---

## 零、先说清楚：改名不是靠洗，是靠补

诊断了全库 26,001 个视频后的结论：

| 问题 | local 2,552 | 115 13,219 | pikpak 10,230 | 性质 |
|---|---|---|---|---|
| 站点前缀 `www.98T.la@` | 10 | **3,998** | **2,479** | 噪声，可洗 |
| 多余空格 / `.mp4.mp4` | — | 221 | 507 | 噪声，可洗 |
| 重复序号 `(N)` | 486 | 2,971 | 1,916 | **陷阱：是唯一区分位，不可剥** |
| 纯数字名 `001.mp4` | 648 | 537 | 805 | 空名，洗不出信息 |
| UUID / Telegram 媒体 ID | 98 | 410 | 286 | 空名，洗不出信息 |
| iPhone / 相机导出 | 70 | 510 | 214 | 空名，洗不出信息 |
| **真乱码（编码损坏）** | **1** | **1** | **0** | 几乎不存在 |

两个反直觉点：

1. **几乎没有真乱码。** 全库只有 2 个文件是编码损坏。看着像乱码的其实是
   `009bd2e1-8167-….m4v`（UUID）、`5_6231074351865665531.mp4`（Telegram 媒体 ID）、
   `001.mp4`（纯数字）—— 不是坏掉的名字，是**从来没有过信息的名字**。
2. **`(N)` 不是重复，是唯一区分位。** `1 (126).avi` / `1 (129).avi` 去掉括号数字后
   2,971 个文件全部撞名。这是最容易误伤的一类。

所以：**规范命名的输入不是旧文件名，是元数据。**
先把归属识别（关键帧）、番号反查、目录归类做完，再按模板把元数据渲染成文件名。
顺序反了就只能得到「另一个没信息的名字」。

## 一、模板

两套主体，一套共用修饰符。

### 1.1 番号型 —— 有厂牌番号的

```
{番号}{修饰符}.{ext}

ABW-123.mp4
ABW-123-C.mp4          中文字幕
ABW-123-UC-CD1.mp4     无码流出 + 中文字幕 + 第一片
FC2-PPV-3312576.mp4
```

番号一律**大写 + 单连字符 + 数字不补零到 4 位以上**：

| 原样 | 规范化 |
|---|---|
| `abw123` / `ABW_123` / `ABW 123` | `ABW-123` |
| `IPVR00296` | `IPVR-296`（前导零剥到 3 位） |
| `FC2PPV-3312576` / `FC2-3312576` | `FC2-PPV-3312576` |
| `HD-abp-758` / `Jav.li_MIAD573` | `ABP-758` / `MIAD-573`（前缀是渠道，丢弃） |

### 1.2 创作者型 —— 无番号的（你库里的大头）

社区没有现成标准，这套是本项目自定的：

```
{创作者} - {日期} - {标题}{修饰符}.{ext}

一个ren - 20250312 - 异域风情.mp4
古河君 - 20240918.mp4                 无标题时省略该段
Yigeren33 - #003 - 偷窥后入视角.mp4    无日期时用稳定序号 #NNN
```

- 创作者用 **Stash 里的 Performer 主名**，别名不进文件名（别名进 Stash 的 alias_list）
- 日期 `YYYYMMDD`，来源优先级：文件名里已有的 > 拍摄时间(ffprobe) > 入库时间
- 标题截断到 60 字符，去掉所有引号书名号和站点/推广文字
- **`#NNN` 序号必须稳定**：一旦分配写进账本，此后不再重排。这是替代 `(N)` 的方案 ——
  同样是唯一区分位，但至少带了创作者名。

### 1.3 修饰符（两套共用）

按下表顺序拼接，全部可选，各出现至多一次：

| 后缀 | 含义 | 判定依据 |
|---|---|---|
| `-C` | 中文字幕 | 内封字幕流 / 原名含「中文字幕/字幕/CH/ChineseSub」 |
| `-U` | 无码流出 / 破解 | 原名含「无码/破解/uncensored/leak」 |
| `-UC` | 无码 + 中文字幕 | 上两条同时成立时用这个，不写成 `-U-C` |
| `-4K` | 2160p 及以上 | ffprobe height ≥ 2000 |
| `-CD1` `-CD2` … | 分片 | 原名含 CD1/part1/A/B 且同目录有兄弟文件 |

**只标 `-4K`，不标 720p/1080p。** 分辨率 ffprobe 随时能读，写进文件名是冗余；
只有「是不是 4K」会影响你选片，才值得占文件名的位置。

`-C` / `-U` 是 JAV 圈和 Emby/Jellyfin 刮削器的既有惯例，跟着用，
好处是 JavSP、MDCx、renamerOnUpdate、Emby 都认。

## 二、执行分三档

### 档 1 · 净化（可立刻做，无风险，纯删噪声）

只删噪声位，不动信息位：站点前缀、`.mp4.mp4`、连续空格、扩展名前空格。
影响约 **6,500 个文件**（115 约 4,000 + pikpak 约 2,500 + local 10）。

⚠️ **绝不批量剥 `(N)`。**

### 档 2 · 套模板（等识别结果出来）

只对**已确认归属**的文件做。当前进度：

- 115 已归属创作者 5,145 / 13,219
- 115 番号 916 个正在反查（r18.dev 多源，命中率约 60–75%）
- 115 D 类 707 张识别页已出，待读

### 档 3 · 不动

档 2 之后仍无归属的（UUID / Telegram ID / 纯数字里补不出信息的那部分）—— **不改名**。
换一个同样没信息的名字没有意义。这些文件的信息进 Stash 的 Performer/Studio/Tag，不进文件名。

### 一个必须先定的取舍

**115 / PikPak 上那 6,477 个带站点前缀的文件，值不值得改？**

改名要调网盘 API 六千多次。而如果终态是那个按心情/tag/创作者检索的 Web 界面，
**文件名根本不会出现在 UI 上**，收益接近零。

我的倾向：**本地库做档 1 + 档 2；网盘只做档 2 里已确认归属的部分，其余不动。**

反过来说，档 2 在本地是**有硬价值**的，理由不是好看：
**文件名是元数据的最后备份。** Stash 库炸了、ledger 丢了，能重建的只有目录 + 文件名。
把归属固化进文件名 = 防灾。

## 三、用现成轮子，别自己写重命名器

### 3.1 renamerOnUpdate（Stash 官方社区插件）—— 这就是执行层

`stashapp/CommunityScripts` 里的 `renamerOnUpdate`：按模板从 Stash 元数据渲染文件名，
Scene 更新时自动触发，也支持批量。有 dry-run，有日志，可回滚。

**这直接改变了做法：不写重命名脚本，而是**

```
补 Stash 元数据（Performer / Studio / code / date / tag）
        ↓
配 renamerOnUpdate 模板
        ↓
dry-run 出清单 → 核对 → 执行
```

我这两天做的目录归类、关键帧识别、番号反查，全都是在喂第一步。
Stash 的 `code` 字段就是为番号准备的，`custom_fields` 可以放 `-C`/`-U` 这类修饰位。

### 3.2 番号元数据源（已实测，2026-08-13）

| 源 | 形态 | 实测 | 用途 |
|---|---|---|---|
| **r18.dev** | 干净 JSON API，无 Cloudflare | 4/4 命中，未遇限流 | **有码主力**，附带 categories 可直接转 Tag |
| **avsox** | HTML | 可用 | 无码 / FC2 主力 |
| **javbus** | HTML | **2 分钟就 403** | 只做兜底，带 5 分钟冷却 |
| javdb | HTML | 有 Cloudflare + 社区 scraper 长期报证书错误 | 不用 |

**教训：单源必被限流。** 第一版只打 javbus，跑到第 25 个就 403 停住。
换成 r18 优先的三源级联后，75% 命中且无限流。
这正是 JavSP / MDCx 的做法（它们聚合 airav / avsox / javbus / javdb / javlib / jav321 / mgstage / prestige）。
JavSP 不在 PyPI（独立应用，会自己搬文件），所以这里只借它的**多源级联思路**，不整包引入。

`rm-javlookup.py` 已按此重写。

### 3.3 其他环节的轮子（待评估，不局限 JAV）

| 环节 | 轮子 | 说明 |
|---|---|---|
| 观看统计 | **Stash 内置** | 见《总体方案》§5.1，字段全有，不用造 |
| 追更 / RSS | **RSSHub** | 5000+ route，Pixiv / Fanbox / Fantia / Kemono(含 DLsite/Patreon) 都有；Fanbox 和 Fantia 需要塞 cookie |
| RSS 阅读后端 | **miniflux / FreshRSS** | 自托管，有 API，可被前端调 |
| 仪表盘外壳 | **Homarr / Homepage / Dashy** | 搜集站导航那块直接用，别自己写 |
| 自动抓取 | **Flexget / autobrr** | 规则驱动的订阅抓取 |
| 去重 | **Czkawka** | 已有 SHA1 方案，此项备用 |
| 元数据共享 | **StashDB / ThePornDB** | ⚠️ 需要外传指纹，与既定边界冲突，**默认不启用** |

## 四、边界（不变）

- 出网的只有番号 / 作品名本身，不带路径、文件名、目录结构、指纹
- 改名一律先出 CSV 预览 → 核对 → 执行 → 比对文件数与总字节
- 全程留日志于 `R:\Resources\Migration_Logs`
- 只动 `R:`、`%LOCALAPPDATA%\Stash`、账本产物
