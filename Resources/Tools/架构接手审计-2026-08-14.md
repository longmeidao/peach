# 架构接手审计（2026-08-14）

## 结论

项目整体方向正确，可以继续做，不需要推倒重来。

真正的产品不是“23 TB 文件整理器”，而是一个默认本地自托管、可安全远程访问的私人内容系统：统一索引资源，采集真实消费信号，再用受控随机和显式反馈生成推荐。在线追更、外部数据源和 AI 是正式能力，不再受“只在本地/局域网、绝不联网”的旧边界。先做“能播、能埋点、能反馈”的 Peach Web 壳仍是正确优先级。

当前适合把它视为一个已跑通核心闭环的原型，而不是已经稳定的长期平台。

项目仍处早期，用户已允许对未发布代码、接口和临时结构做破坏性重构，以换取速度、性能和更清晰的边界。真实媒体、账本、行为数据、凭据与公网配置不在该授权内。

## 2026-08-14 新架构结论

- FastAPI 化，前后端职责拆分但继续单体部署；旧 HTTP 服务只作短期迁移脚手架。
- Media Engine 统一 filesystem/Stash/后续 native backend；Stash 可以完全移除，但必须分阶段对账。
- AI Provider 分 Inference 与 Agent 两类。视觉识别、元数据融合、推荐解释、追更归纳和维护代理是主要价值；AI 不直接成为真相源。
- 当前不做完整多账号，但正式迁移预留 `app_user/profile`；凭据只保存引用，不进入 ledger。
- 远程访问未来走 VPN/Tunnel，或 DDNS + 反代 + HTTPS；本轮不开放公网。

## 正确的职责边界

### ledger.db：跨来源的唯一真相源

负责本地、115、PikPak、在线四类资产的统一身份、路径、探测结果、标签投影、消费状态和待处理任务。Peach 的列表、筛选、推荐和反馈应以 ledger 为准。

### Stash：本地视频的专业元数据与兼容层

Stash 只覆盖本地约 2,552 个文件，适合继续承担本地场景元数据、Performer/Studio/Tag 管理，以及必要的导入/导出兼容；不应再被描述成整个 Web 的后端或全局真相源。

### Peach Web：消费入口与行为采集层

通过资产 ID 串流，不向浏览器暴露文件路径；默认排除计费的 PikPak；写回播放、进度、反馈和待处理状态。它不应承担批量文件整理、删除或元数据爬取。

### 离线工具：加工与同步层

扫描、ffprobe、接触表、SHA1、识别、标签和重组继续由独立脚本完成。长任务与 Web 服务解耦是正确设计。

## 主要问题与优先级

### P0：隐私访问边界尚未真正落实

代码支持 token，但当前运行实例 token 为空，并监听 `0.0.0.0:80`。这等于同一可达网络里的设备无需口令即可浏览和串流私人库。应在确认用户设备访问方式后启用固定口令，并检查 Windows 防火墙只允许“专用网络/本地子网”。本轮先修复了 Cookie 子串误认证问题；启用口令会改变现有访问地址，未擅自切换运行实例。

### P1：行为语义分裂

CLI 使用 `rating=5/1` 表示喜欢/不喜欢，Web 使用 `feedback=dislike/seen`，另有 `play_count`、`o_count`、`watch_ratio`、`leave_ratio`、`play_seconds`、`max_reached`。这些字段能支撑原型，但推荐逻辑若直接混用会产生歧义。

下一步应先写一份行为词典，明确每个动作的唯一含义和投影规则；再增加 append-only 的行为事件表保存时间序列，`asset` 上的累计列只做快速查询投影。不要立即删旧字段。

### P1：数据库迁移没有版本（第一阶段已落地，尚未应用真实库）

新增 `rm-migrate.py`、`migrations/0000..0001` 与 checksum/backup/幂等测试。真实 ledger 当前仍没有 `schema_migration`，待单独维护窗口显式升级；应用启动不自动迁移。

### P1：缺少工程基线（已建立）

已建立 Git 基线 `cc293c7`，排除媒体、ledger、密码和生成物；测试增至 23 项。FastAPI 候选入口
已完整覆盖页面、JSON、标准 Range/HEAD、缩略图和预览资产，并在临时 8900 端口完成双视口
验证。允许更积极拆模块，但每个切片仍必须用临时库和契约测试证明不会破坏真实数据。

### P2：首屏性能与查询模型

手机冷加载实测约 7–8 秒。首页启动同时请求多个聚合查询，90 秒内存缓存能缓解热访问，但进程重启后仍要全表聚合。应先记录接口耗时和查询计划，再针对真实慢查询加组合/部分索引，避免盲目堆索引。

### P2：文档漂移

《总体方案》和《交接文档》的旧路线已增加覆盖性更新；历史段落保留决策脉络，但当前实现以文首更新、ADR 和专项审计为准。
