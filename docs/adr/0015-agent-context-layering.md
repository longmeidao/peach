# ADR-0015：智能体上下文分层与清退机制

- 状态：已接受
- 日期：2026-08-17

## 背景

`AGENTS.md` 与 `docs/HANDOFF.md` 是持续追加的文件。追加成本不对称：`AGENTS.md` 每轮对话都被
完整载入并消耗预算，而其中大量条目（迁移流程、限流标定、取证协议）只在特定任务里才成立。
条目越多，真正的硬门槛越容易被稀释。`docs/HANDOFF.md` 已达 215 行，同时混装长期规则、
一次性事故证据和按日期记录的批次说明，读者无法只取自己需要的一段。

用户提供参考视频 `https://www.youtube.com/watch?v=e1snsuY4lTI`
（`My AGENTS.md & SKILLS.md Breakdown (Don't copy them)`）。取证过程如实记录：本方直接抓取
失败——youtube.com 只返回页脚导航，`youtubetotranscript.com` 对 WebFetch 返回 HTTP 403，
浏览器打开落在机器人验证页且未绕过；**逐字稿由用户于 2026-08-17 手动提供**，本 ADR 采用的是
这份用户提供的转写内容，不是本方独立取证的结果。

从该逐字稿采纳的观点（只取方法论，不取作者的具体条文——视频本身也明确反对照抄）：

1. skill 的 `description` 常驻上下文，技能未触发时也在花预算，因此它应写触发关键词而不是功能摘要。
2. 一个技能同时管两件常被单独需要的事就该拆开，各写各的触发词。
3. `AGENTS.md` 与 `README.md` 的读者不同：README 说明项目是什么，`AGENTS.md` 说明改动它之前
   必须知道什么。
4. 术语表的主要价值不是让模型听懂你，而是让模型用你的词回答你。
5. 入口文件应声明哪些是「好的默认、用户可覆盖」，避免模型与当场指令对抗。
6. 最常见的缺陷是「改动只覆盖了自己测试的那条路径」，因此需要一份显式的表面清单。
7. 规则应该由历史失败的统计得出，而不是凭印象追加；照抄别人的规则等于引入别人的失败模式。
8. 坏例/好例成对给出，比抽象形容词更能改变模型行为。

其余可复现材料与本项目自身证据：

- push 与 pull 两种上下文模式的区分（常驻文件 vs 按 description 触发载入的 skill），见
  <https://blog.logrocket.com/context-engineering-for-ides-agents-md-agent-skills/> 与
  <https://chrisreddington.com/blog/building-your-agent-toolbox/>。
- 本项目 `docs/HANDOFF.md`「重复错误复盘（2026-08-16）」的结论：反复犯的错根因是
  「文字提醒没有变成执行门槛」。因此分层规范本身也必须带可执行检查，否则它会成为下一条
  被忽略的散文。

## 决策

### 四层归属

| 层 | 位置 | 内容 | 预算 |
| --- | --- | --- | --- |
| L0 全局配置 | `~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md` | 与仓库无关、每个任务都成立的身份与语言偏好 | ≤ 20 行 |
| L1 项目入口 | `AGENTS.md` | 进入 Peach 必须先成立的边界、硬门槛、术语表与技能索引 | ≤ 90 行 |
| L2 仓库文档 | `README.md`、`docs/**` | 事实、数字、历史证据与架构决策，被指向时才读 | 无行数上限，但按主题分节 |
| L3 技能 | `.claude/skills/<name>/SKILL.md`、`~/.claude/skills/<name>/SKILL.md` | 某类任务开始时才需要的可执行流程 | 每个 ≤ 120 行 |

### 预算只能降不能升

预算的意义是「写不下就说明内容该下沉」。如果每次触发都靠抬阈值解决，它只是橡皮图章。
本次改动本身就是反例：`AGENTS.md` 涨到 82 行后，预算在同一批里被从 70 改成 90。结论虽然站得住
（术语表与覆盖声明按判据 1 属于常驻构件，下沉即失效），但过程是先超标后改数。因此定死：

- 预算随时可以调低。上调必须在 `scripts/check_context_budget.py` 的 `BUDGET_CHANGES` 里追加
  「值 / 日期 / 理由」，理由必须说明这些内容为什么无法下沉到 `docs/` 或某个技能。
  理由为空或仍写「初始值」的上调直接判错。
- `MAX_EVER` 是不可越过的天花板：入口文件（`AGENTS.md`、`CLAUDE.md`）200 行、`SKILL.md` 500 行、
  `description` 1024 字符。后两个直接采用 Anthropic 官方 skill authoring 的值（正文建议 < 500 行、
  description 硬校验 1024 字符）；入口文件没有官方值，由本项目定死为 200 行。
- 内部预算（`AGENTS.md` 90、`SKILL.md` 120、`description` 200）一律严于天花板，且只能降不能升。
  天花板管「绝不越过」，内部预算管「当前写作纪律」，两者不是一回事。

能自动挡住的只有「留痕」和「封顶」。脚本判断不了某段内容能不能下沉，那是复核时看理由站不站得住。

### 判据（决定一条内容写在哪一层）

1. 不遵守会直接损坏真实数据、破坏生产或产出假结论，且每类任务都可能触发 → L1，写成一行
   祈使句，并指向可执行入口（脚本、测试、hook）。
2. 只有做某一类任务才需要，且内容是「步骤」而不是「事实」 → L3 技能。
3. 内容是事实、数字、事故证据或历史结论 → L2 文档。技能只引用文档路径，不复制事实，
   避免同一数字出现两份且各自漂移。
4. 与本仓库无关、跨项目成立 → L0；超过 5 行的成套流程同样降为全局技能。
5. 只对本次对话有效 → 不写入任何文件。
6. 一条规则只要能变成脚本拒绝、测试失败或 hook 行为，就必须先变成门槛，散文里只留一行指路。

### 入口文件的固定构件

`AGENTS.md` 除边界与硬门槛外，固定包含三件：

- **术语表**：ledger、真相字段、候选、复核产物、实体、表面、门槛、协调者/工作者等。同一件事
  只用一个词，智能体回话时也用这些词。
- **覆盖声明**：风格与流程条目是好的默认，用户当场指令可以覆盖；写真实 ledger、不可逆删除、
  切换生产、处理凭据不在此列，必须同轮显式授权。
- **技能索引**：触发条件 → 文件路径。

`AGENTS.md` 不重复 `README.md`。README 面向「这个项目是什么、怎么跑」，`AGENTS.md` 面向
「改动它之前必须知道什么」。

### 技能写法

- 目录名即 `name`。`description` 常驻上下文，技能未触发时也在花预算，因此写触发场景与关键词，
  不写功能摘要，更不能把步骤塞进去；上限 200 字符。
- 一个技能同时管两件常被单独需要的事就拆成两个，各写各的触发词。
- Codex 不自动加载技能，因此 `AGENTS.md` 用「触发条件 → 文件路径」的表格做索引，让它在
  条件成立时直接读取同一份文件。两个智能体共用同一份内容，不做第二份副本。
- 每个 `SKILL.md` 正文必须有 `最后复核：YYYY-MM-DD` 与 `证据来源：` 两行。

### 清退机制

1. **可追溯**：每条 L1 硬门槛必须能指认触发它的事故或证据（提交号、CSV、实测记录）。
   复核时指认不出来源的条目直接删除。照抄外部模板的条文因此天然不合格：它对应的是别人的
   失败模式，在本仓库没有可指认的来源。
2. **失败模式审计**：每次 minor 发布前，或连续踩同类坑时，审计本机会话与 Git 历史，按模型和
   harness 统计高频失败，产出可核对的清单。高频且可自动检测的做成门槛，只能靠判断的写进
   `AGENTS.md` 或技能并配坏例/好例，已被门槛覆盖的直接清退。
3. **过期报告**：`最后复核` 超过 180 天的技能由 `scripts/check_context_budget.py` 报告，
   退出码 3；复核后要么更新日期，要么删除。
4. **触发复核的时机**：相关实现被删除或重写；规则已被可执行门槛覆盖；预算检查失败；
   失败模式审计给出新结论；每次 minor 版本发布。
5. **删除动作**：确认 Git 历史保留原文后，在同一提交里整段删除，不留「已废弃」注释。
   与项目既有规则一致：Git 是归档，不为历史保留死接口。
6. **被 ADR 取代的段落**只留一行指向该 ADR。
7. **执行门槛**：`tests/test_context_budget.py` 在唯一测试入口 `& .\scripts\test.ps1` 中强制
   校验行数预算、技能 frontmatter 与 `最后复核` 行的存在。日期是否过期只报告，不使全量测试
   因时间流逝而变红。

## 放弃方案

- 继续往 `AGENTS.md` 追加：每轮付全量成本，且硬门槛被非门槛条目稀释。
- 把全部规则拆成技能：Codex 不自动加载技能，模型也可能不召回；数据安全类规则必须常驻。
- 恢复按日期新建交接文档：已被现有工作契约禁止，且正是当前混装问题的来源。
- 直接复制社区 `AGENTS.md` 模板：证据不可得，且与本项目实际事故无关。

## 后果

`AGENTS.md` 回到「压缩索引」定位，新增规则前必须先回答判据问题，默认落到技能或文档而不是入口。
代价是多了一次跳转：Codex 需要按索引表主动读取技能文件，若索引与文件不同步就会读到空。
`tests/test_context_budget.py` 覆盖索引所列路径是否存在，防止这种漂移。

首批迁移已完成：`peach-worktree`、`peach-ledger-write`、`peach-surfaces`、`peach-batch-jobs`、
`peach-reference-evidence`、`peach-context-rules` 六个项目技能，以及全局 `traffic-diagnostics`。
`AGENTS.md` 预算从 70 行放宽到 90 行，多出来的额度专用于术语表与覆盖声明这两件常驻构件；
其余新增内容仍应落到技能或 `docs/`。

2026-08-27 复核已清退 `docs/HANDOFF.md` 中会变化的外部测量、旧测试数字、模型能力说明，以及
已由技能、测试或 `docs/STATUS.md` 承担的重复事实；长期文档从 259 行降到 157 行，预算同步降为
180 行。运行态仍以 `docs/STATUS.md` 为单一真相位置。
