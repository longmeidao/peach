# ADR-0033：联网来源只补账本没有值的字段

- 状态：Accepted
- 日期：2026-09-15

## 背景

既有库采集缺哪个字段就去问 r18.dev，但抓回来的是整份资料，`_merge_candidates` 把资料里
每个认得出的字段都并成候选，不看当初缺的是哪个。真实账本 2026-09-13 那次采集的结果：
769 个番号资产、4142 条候选，全部来自 r18dev，其中

- 1492 条取值与账本现值一模一样（studio 745、release_date 711、series 32、title 4）；
- 1165 条是英文机翻对日文原题（title 744、series 421）；
- 1448 条补的是真正的空字段（performers 667、tags 697，另 84 条）；
- 37 条是发行日期差几天（DMM 的配信日对发售日）。

也就是说复核队列里 64% 的题不是分歧：一半是同一个值对同一个值，另一半是写法差异。
它们之所以产生，是因为这些资产大多只缺 performers 和 tags，一次抓取顺带把标题、厂牌、
系列、发行日期各拖出一条候选。

ADR-0029 已经为本地 NFO 判过同一件事：英文机翻与日文原题的差异是写法，不是事实分歧。
那条规则只覆盖 NFO 给出的字段，账本自己已有的值不在其内。

## 决策

**一、账本已有值的字段，联网来源不再产生候选。** 联网来源只补空字段，与 ADR-0029 给
本地 NFO 定的边界一致。

**二、演员与标签按账本里的关联判空。** 这两个字段不在 `asset` 表上，取行时从
`asset_entity`、`asset_tag` 一并读出来。不读就是每部片都被当成缺演员缺标签：本机 770 个
资产里 645 个早有女优关联、752 个早有标签，却每部都去问了一次 r18，再把账本的中文规范名
（`凉森玲梦`）对上来源的日文名（`涼森れむ`）变成一道复核题。

**三、取值与现值相同的候选一律不进队列，本地 NFO 也一样。** 值相同时没有可判断的内容。

要把已有值换成来源的写法，仍走详情页手动编辑，或先清空该字段再采集。

## 理由

- 复核的价值在于人替机器判断分歧。同值题与写法题只消耗注意力，还把真正要判断的几十条
  淹在几千条里。
- 判据放在候选生成这一步，而不是复核页的过滤器：不生成就不会写进 CSV，也不会被自动落库
  的路径看见，一处管住全部下游。
- 账本已有值的来路（旧导入、扫描、用户编辑）在这里不需要区分。单人自托管的库里，用户要
  改哪个字段自己知道，清空再采集比维护一套「谁能顶掉谁」的分级简单得多。

## 被否决的方案

- **只过滤判定为英文的候选。** 语言判定要维护一套阈值，而且解决不了 1492 条同值题。
- **只在复核页隐藏。** 候选照样写进 CSV 与自动落库路径，问题只是看不见。
- **按字段归属决定要不要出候选（无主字段才出）。** 本机这批值几乎都没有归属记录，等于
  没有过滤；真要按归属分级，得先给历史数据补一轮归属，收益是零。

## 后果

- 采集只为空字段产生候选；本机这批队列清掉重跑后，剩下的是真正没有值的那几十条。
- 每部片都问一次 r18 的行为跟着消失：演员和标签齐全的片不再触发联网请求。
- 已经写错的值不会再由采集提出更正，要用户自己清空字段或在详情页改。
- ADR-0018/0025 的自动落库与分歧判定不变，只是进入它们的候选少了。
