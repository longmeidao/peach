# ADR-0010：先复用、再重实现

- 状态：Accepted
- 日期：2026-08-14

## 背景

项目结构迁移删除了旧文件名，但多项实现实际以高相似度迁入 `scripts/`。按旧文件名查找导致现有 `scripts/scrape_codes.py` 被误判为缺失，并准备从 Git 恢复旧 scraper。迁移期间也出现过未对照已验证实现而重写 mDNS、重复媒体抽象、重复计费/磁盘闸门等问题。

## 决策

- 新增或恢复实现前，按能力、输入输出和数据副作用搜索当前树，再检查 `docs/REUSE.md` 和 Git 历史。
- Peach 只自研领域差异：实体身份、行为、跨来源绑定、成本/隐私、review/provenance 和任务语义。
- 协议、解析、媒体编解码、搜索基础设施、播放器、图标和调度优先使用成熟依赖；首个真实消费者、固定版本和隔离测试必须同批落地。
- 运行时只保留一个正式 abstraction。迁移 facade 若未接入生产，不得算作能力完成。
- 用户不承担代理间信息同步；事实、规则和决策分别写入 STATUS、HANDOFF/REUSE 和 ADR。

## 被否决的方案

- 因旧文件名消失就从 Git 恢复整份脚本。
- 为统一表面接口，把 Codex/Claude agent runtime 与普通 inference API 强行等同。
- 在没有首个消费者时提前堆积依赖。
- 保留两套生产 abstraction，依靠调用者自行选择。

## 后果

每项能力多一道短审计，但能避免迁移回归、重复维护和不必要的协议实现。`docs/REUSE.md` 成为可更新的实现索引，不替代具体 ADR 和测试证据。
