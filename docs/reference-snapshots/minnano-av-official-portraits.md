# minnano-av 与事务所公式站的女优图实测

- 取证日期：2026-09-01
- 取证方式：`urllib` 带常规浏览器 UA、经本机代理请求，记录状态码、字节数与 SHA-256；
  图片尺寸用 Pillow 打开实际字节测量，不依赖页面上写的宽高属性
- **不登记进 `docs/reference-sources.json`**：那张表要求每个来源有可哈希的上游快照，
  这里记的是「哪个站能取到够格的女优图」，站点改版就会变。复核按下面的方式重测。

## 起因

72 位有作品的 performer 缺头像，其中 45 位在 Gfriends 当前索引里根本没有。用户提出
minnano-av 能搜到人，且页面能顺到事务所公式站，那里的 poster／写真质量最高。这份记录
要回答的是：这条路能不能真的补上 Gfriends 补不上的那部分。

## 实测

### 一、minnano-av 女优页

`https://www.minnano-av.com/actress494354.html` → HTTP 200，99,234 字节，
SHA-256 `2b2ae5eb5303c944b194f2048c6391cf230740c2cf3b2a8cca9a0cba49d63190`。

资料表结构稳定，可按标签取值：

```html
<td><span>标签</span><p>纯文本或 <a href="...">链接</a></p></td>
```

这一页出现的标签：`血液型`、`出身地`、`ブログ`、`公式サイト`。前两个指向站内检索，
后两个是外链——`ブログ` 给的是 Twitter，`公式サイト` 给的是事务所站。

女优本人的头像路径形如 `/p_actress_125_125/<桶>/<id>.jpg`，路径里的 `125_125` 就是
真实尺寸：**125×125**。头像门槛是长边 ≥500、短边 ≥300，所以 **minnano-av 自己的图
一张都不够格**，它的价值在于外链而不是图。

### 二、事务所公式站

`公式サイト` 给出的是 `http://official.nax-pro.com/model/`——事务所的**模特索引页**，
不是某一位的页面。用户看到的 `/model/14717` 需要再走一步才能定位。

`http://official.nax-pro.com/model/14717` → HTTP 200，53,485 字节，
SHA-256 前缀 `33dde63b0de1dd7f`。站点是 WordPress，图在 `/naxwp/wp-content/uploads/`。
逐张下载后实测：

| 图片 | 实测尺寸 | 字节 | 门槛 |
| --- | --- | --- | --- |
| アイキャッチ画像 | 600×790 | 218 KB | 合格 |
| ギャラリー画像 ①〜④ | 1024×1820 | 147–189 KB | 合格 |

文件名里的 `-1024x1820` 是 WordPress 的缩放后缀，去掉后缀的原图只会更大。作为对照，
Gfriends 那 18 个已判 ok 的候选里最大的一张是 2880×1800，多数在 500×600 一档。

## 结论与差距

- minnano-av 不能当图源（125×125），但它是**唯一能从女优名走到事务所站与社媒的入口**，
  用户提的「参考 beeg 的社媒链接」也从这里取。
- 事务所公式站的图确实够格，且明显高于 Gfriends 的常见档位。
- **缺口在中间那一跳**：minnano-av 只给事务所索引页，从索引定位到具体模特还需要一步；
  而且不同女优的事务所各不相同，`nax-pro` 只是其中之一，不能把它当成通用形态。

因此这条路要接进来至少还需要两件当前**未取得**的证据：从女优名定位 minnano-av 页面的
检索形态，以及从事务所索引定位到模特页的通用做法。在拿到之前不要按 `nax-pro` 一家的
结构写解析器——那会变成只对一家有效、对其余静默失败。
